# MortisBuffManager 3.0.0 设计与验证

- 全局模式和上限：预选、地图进度抽选、竞争三种。所有玩家共用 0–64 上限，没有逐玩家覆盖。Realms 单行设置和 DMF 使用同一配置。击杀权重由房主在 DMF 全局调整。
- 预选沿用按角色保存的数据，进入任务后锁定编辑；降低上限保留历史。两种抽选模式开局各一次，每轮一次三选一消耗一点。
- 进度来源：已准备就绪的线性主路径首次达到 10% 至 90% 的每个 10% 节点、去重后的主目标、死灵试炼波次。时间不产生奖励。原版没有路径时可能返回 100%，因此必须先检查路径可用性。
- 竞争只在主机处理已归属到真人玩家的死亡事件，普通/尸潮 0.25、特感 5、精英 2.5、Boss 50，每 100 点发一次，保留余量；死亡单位弱引用去重。
- 每个角色一个当前选择及后续机会计数。当前选择 60 秒超时随机，下一轮从当前时刻再给 60 秒；长帧一次最多解决一个超时。原生候选唯一、不重复已获得项，耗尽即停止。
- Ctrl+1/2/3 直接读取按键，不修改输入服务、鼠标和角色状态。菜单与打字优先。实际 UIHud 使用原版材质、入场淡入和选中淡出；卡片 328×196，间距 12。长文本原版测量缩放，必要时原版省略。原版 Tab 从 Buff extension 读取已应用项，无需改写 Tab。
- 主机协调器协议 4：当前玩家身份、会话代数、请求令牌、状态序列、角色和候选 ID 校验。加入、换角色、连接变化刷新授权；退休令牌拒绝离开后的旧消息。重新注册 Realms 回调支持重复房间。
- 客机每 2 秒确认状态和资源，活跃选择每 0.5 秒同步，未确认选择重发。主机只给握手有效且资源就绪的玩家奖励；8 秒通信租期失效暂停对应玩家。离开/关闭/资源等待保留本任务同角色已得奖励及当前剩余选择时间，其他玩家照常继续。换任务清空；切模式建立新记录。
- Realms 房主显示两模组各自的部署状态及可用版本，异常提示按状态去重。Talent 协议仍为 6，仅增加可选版本/数据就绪字段与提示；保留原有合法构筑投影和独立离开清理。两者不提供房主迁移。
- 两模组各自扩展原生玩家 grid，复制蓝图而非修改共享蓝图。DMF 会自动解开已挂接函数的副本，故以转发函数保持另一模组挂钩链；共享弱引用祖先标记避免重复套用。输入只在控件更新调用内共享，分别禁用时仅清理自身。
- 四人同时启用：内容高度 836，原生可视高度 707，沿用原生滚动条显示余下内容。已测试两种加载顺序、30 次重复挂接、四次房间重建、主客机切换、掉线及分别禁用。
- 独立发布 release/3.0.0，ZIP 仅 MortisBuffManager 根目录。三语资料及图片单独存放，旧版本不修改。不启动游戏，不部署 Vortex，不上传 Nexus。

- 竞争个人 HUD：下方中央 220×38 安全区域，四种本地样式（条、条＋百分比、百分比、隐藏），默认条＋百分比。局部矩形根据样式压缩；不修改房主规则或奖励。抽选时继续显示，其他模式隐藏。
