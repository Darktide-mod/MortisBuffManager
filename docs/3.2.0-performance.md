# 3.2.0 性能与抽选改动

- 竞争模式累计获得全部可用奖励次数后，停止击杀进度累加和敌人分类，并关闭进度显示。排队中的奖励仍可领取；房主提高上限后恢复计数。
- 角色设置、职业与技能条件、原版候选池、已选列表和本机 HUD 快照按实际变化复用。原位修改天赋表、角色重生、处理器更换和原版排除表变化会使相关缓存失效。
- 普通任务中，领取奖励或修改设置后的 Buff 核对仍在 0.5 秒内进行；稳定状态采用 5 秒补偿核对。原版死灵模式保留异步候选池排重。没有修改原版 Buff 模板、数值、触发次数或网络编号。
- 主机按状态变化同步，客机仍每 2 秒请求同步，8 秒失联保护及选择重发保留。修正客机关闭 mod 时发送的协议号。
- 空闲 HUD 不进行空绘制，不在绘制阶段再次构造快照。按键空闲状态复用表。任务识别和网络注册移到现有 0.5 秒处理周期，连接变化仍即时检查。
- 路线、Buff 等级与效果说明使用原版名称和格式化器；卡片不会裁短效果说明，选中时闪亮、抬起并淡化其他选项。自动路线奖励及最后一个自动获得的候选，选后逐条显示完整效果。

验证：本项目全套 Lua、原版数据、网络重连、禁用和输入回归；128 种原版职业／技能组合；127 Buff 的 60 秒调用次数测试中候选池零重复构造，后续 1000 次击杀零敌人分类，补偿核对不超过 13 轮。奖励变化、原位天赋修改、重生与外部移除恢复单独验证。使用真实 HUD 更新／绘制回调生成内部布局检查，覆盖英语、简体中文、繁体中文以及 16:9、16:10、21:9、4:3。

这些是离线调用次数与行为检查，不能换算成实测帧率提升。原版爆炸、范围查询、电击和手雷衍生 Buff 仍可能消耗较多主机资源；未通过削减其效果来提升性能。未启动游戏、修改 Vortex 或部署本机。

3.2.1 補充：自動獲獎展示復用抽選卡片元件，同輪獎勵一起展示 2 秒，計時器另行保留下一次抽選的完整 60 秒。
